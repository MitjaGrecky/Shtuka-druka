# 18. Замер мощности: M93 и Dell (31.10–06.11.2026)

Статус: замер на Dell сделан; замер на M93 не выполнен (открыт). Вопрос: хватит ли процессора на 16 дорожек со старта и на 32–64 позже (R11, R36). Программа: `bench/shtuka_bench.cpp`, AGPL-3.0 (R20, R69).

## 1. Что считает программа

- **Эталонная дорожка:** 8 голосов, у каждого фильтр и огибающая. Нечётные дорожки — вейвтейбл (2 осциллятора на голос), чётные — сэмплер с интерполяцией. Дальше фильтр, драйв, хорус, компрессор и 4 посыла (R47, R38).
- **Шины:** 2 реверба (Freeverb-класс) и 2 дилея, общие.
- **Параметры:** 48 кГц, блок 128 отсчётов = 2,67 мс (t = N / fs).
- **Нагрузка** = время обработки блока / длительность блока. Критерий: p99 < 70 %.
- **Четыре прогона:** (1) перебор числа дорожек на 1 ядре и на всех; (2) цель R11 — 16 дорожек на всех ядрах, 60 с в реальном времени, опоздания блоков (это и есть щелчки); (3) тяжёлые синты — 16 голосов; (4) 96 кГц с блоком 256 (та же задержка 2,67 мс) — [20](20_usb_audio_interface.md), раздел 7.
- Дорожки раскладываются по ядрам, шины считаются после них.

## 2. Замер на M93 (не выполнен)

M93 Tiny (i3-4150T, R19). Решено: Linux начисто (Ubuntu Studio 26.04 LTS, ядро lowlatency), вместо Home Assistant. Установка ≈ 30–40 минут. Прогон: `cd ~/bench && ./run_bench.sh`, 15–20 минут, ничего не запускать параллельно. Результат — файл `~/shtuka_bench_results.txt`.

Открыто: результат M93; брать ли N100DC-ITX как второй стенд; повторить замер на Dell под Linux (с флешки).

## 3. Облако Claude (только проверка программы)

2 потока Xeon 2,1 ГГц, общий процессор: до 48 эталонных дорожек на 1 ядре, до 56 на 2 потоках при p99 < 70 %. Опоздания из-за соседей по серверу — стабильность не оцениваем.

## 4. Замер на Dell (06.11.2026)

Файл `bench/results/2026-11-06_dell-latitude-7212_i7-8650U_win11.txt`. Dell Latitude 7212 Rugged: Intel Core i7-8650U (4 ядра / 8 потоков, 2017), 16 ГБ, Windows 11 Pro, от сети, схема «Balanced». Программа собрана под Windows (`run_bench_windows.bat`); вместо SCHED_FIFO — высокий приоритет Windows.

| Прогон | 1 поток | 8 потоков |
|---|---|---|
| 1. Эталон, 8 голосов, 48 кГц | 28 дорожек | **64** (на 80 — FAIL) |
| 3. Тяжёлые синты, 16 голосов | 24 | 64 |
| 4. 96 кГц, блок 256 | 20 | 56 |
| 2. Цель R11, 16 дорожек, 8 потоков | средняя нагрузка 22 %, p99 47 % | — |

**Вывод:**
- По мощности i7-8650U тянет ≈ 64 эталонные дорожки на всех потоках — в 4 раза больше цели R11 (16). Цель занимает около пятой части процессора (p99 19 %).
- 96 кГц стоит ≈ 13 % ёмкости (56 вместо 64).
- **Стабильность на Windows не измерить:** почти половина блоков «опаздывает» уже при средней нагрузке 22 % — это таймер Windows (ожидание 2,67 мс с точностью около 1 мс). Строки «realtime check» не учитываем. Стабильность — только на Linux.
- На 1 потоке Dell (28) слабее облачного ядра (48): мобильный процессор при «Balanced» и фоновые задачи дают выбросы p99.

## 5. Как читать результат M93

| Результат на M93 | Что значит |
|---|---|
| 16 дорожек на всех ядрах, 0 опозданий за 60 с | класс Pi 5 годится для 16 лёгких дорожек; N100 (≈ 2× по многопоточности) даст запас на 32 |
| 16 проходят по нагрузке, но есть опоздания | упираемся в систему: пробуем PREEMPT_RT, режим performance, отключение энергосбережения в BIOS |
| 16 не проходят | подтверждение R36: база — x86 класса N100 и выше, 8 ядер для 32+ |

**Ограничение:** эталонная дорожка проще настоящих синтов. Тяжёлые пресеты Surge XT и физические модели могут стоить в 3–10 раз больше. Поэтому прогон 3 и запас 30 % от критерия 70 % обязательны. Следующий шаг — та же нагрузка с настоящими движками (Surge XT, Dragonfly) через JACK.
