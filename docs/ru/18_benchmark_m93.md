# Штука Дрюка: замер мощности на M93

*31.10.2026. **Факт** — из источника, **вывод** — моя инженерная логика, **решено** — решение пользователя.*

## 0. Зачем

Главный открытый риск проекта — хватит ли процессора на 16 дорожек со старта и на 32–64 позже (R11, R36). M93 Tiny с i3-4150T (R19) по мощности на уровне Raspberry Pi 5 (документ 12). Замер на нём даёт нижнюю планку: сколько эталонных дорожек тянет слабый процессор и какой запас нужен от x86 класса N100 и выше.

## 1. Что ставим

- **Решено:** Linux ставим на M93 начисто, вместо Home Assistant (Windows там нет).
- **Система: Ubuntu Studio 26.04 LTS** (выпуск 23.04.2026, [Wikipedia](https://en.wikipedia.org/wiki/Ubuntu_Studio)). Это Ubuntu, настроенная для звука: ядро с низкой задержкой и звуковой сервер JACK из коробки. Ubuntu Studio использует ядро lowlatency, а не отдельное ядро реального времени, потому что его проще поддерживать (там же).
- **Вывод:** для первого замера этого хватает. Ядро с полным PREEMPT_RT сравним вторым шагом, если на lowlatency будут щелчки (PREEMPT_RT вошёл в основное ядро Linux с версии 6.12, документ 12).

## 2. Установка (≈ 30–40 минут)

| Шаг | Что делать |
|---|---|
| 0 | Если в Home Assistant что-то нужно сохранить — сделать резервную копию: «Настройки → Система → Резервные копии». Установка сотрёт диск |
| 1 | На другом компьютере скачать образ Ubuntu Studio 26.04 LTS с ubuntustudio.org и записать на флешку от 8 ГБ программой balenaEtcher или Rufus |
| 2 | Вставить флешку в M93, включить и сразу нажимать F12 — меню загрузки Lenovo. Выбрать флешку |
| 3 | В установщике: язык, раскладка, сеть; тип установки — «Стереть диск и установить» |
| 4 | Имя пользователя и пароль запомнить: пароль спросит скрипт замера |
| 5 | После перезагрузки — обновить систему: Терминал → `sudo apt update && sudo apt full-upgrade -y`, перезагрузить |

Для замера не нужны ни AudioFuse, ни монитор надолго: программа считает обработку звука без вывода в звуковую карту. Монитор и клавиатура нужны только на время установки; дальше можно работать по сети (SSH).

## 3. Замер

| Шаг | Что делать |
|---|---|
| 1 | Скопировать папку `bench` (файл `shtuka_bench.zip`) на M93 флешкой и распаковать в домашнюю папку |
| 2 | Терминал: `cd ~/bench && ./run_bench.sh` |
| 3 | Ввести пароль, когда спросит; подождать 15–20 минут, ничего не запуская параллельно |
| 4 | Прислать мне файл `~/shtuka_bench_results.txt` |

### 3.1 Что считает программа (вывод)

- **Эталонная дорожка:** 8 голосов, у каждого фильтр и огибающая. Нечётные дорожки — вейвтейбл-синт (2 осциллятора на голос, плавный переход между волнами), чётные — сэмплер (воспроизведение с интерполяцией и сменой высоты). Дальше — фильтр дорожки, драйв, хорус, компрессор и 4 посыла (схема R47, R38).
- **Шины:** 2 реверба (класса Freeverb) и 2 дилея — общие на всё устройство.
- **Параметры:** 48 кГц, блок 128 отсчётов = 2,67 мс (формула t = N / fs, документ 12).
- **Нагрузка** = время обработки блока / длительность блока. Критерий из документа 12: p99 (99 % блоков) < 70 %.
- **Четыре прогона:** (1) перебор числа дорожек на 1 ядре и на всех; (2) цель R11 — 16 дорожек на всех ядрах, 60 с в режиме реального времени, считаются опоздания блоков (это и есть щелчки); (3) «тяжёлые синты» — 16 голосов на дорожку; (4) 96 кГц с блоком 256 (та же задержка 2,67 мс) — сколько дорожек остаётся при удвоенной частоте (документ 20, раздел 6).
- **Многоядерность:** дорожки раскладываются по ядрам, шины считаются после них — как в документе 12 («дорожки параллельно, цепочка внутри дорожки последовательно»).
- Код — `bench/shtuka_bench.cpp`, лицензия AGPL-3.0 (R20, R69).

### 3.2 Проверка в облаке (только чтобы убедиться, что программа работает)

На виртуальной машине Claude (2 потока Xeon 2,1 ГГц, общий процессор) перебор прошёл до 48 эталонных дорожек на 1 ядре и до 56 на 2 потоках при p99 < 70 %. Опоздания блоков там есть из-за соседей по серверу, поэтому стабильность по этой машине не оцениваем.

## 4. Как читать результат (вывод)

| Результат на M93 | Что значит |
|---|---|
| 16 дорожек проходят на всех ядрах, 0 опозданий за 60 с | Класс Pi 5 годится для 16 лёгких дорожек; N100 (≈ 2× по многопоточности) даст запас на 32 |
| 16 проходят по нагрузке, но есть опоздания | Упираемся в систему, а не в мощность: пробуем ядро PREEMPT_RT, режим performance, отключение энергосбережения в BIOS |
| 16 не проходят | Подтверждение R36: база — x86 класса N100 и выше, 8 ядер для 32+ |

**Ограничение:** эталонная дорожка проще настоящих синтов. Тяжёлые пресеты Surge XT и физические модели могут стоить в 3–10 раз больше (документ 12: на Pi в Zynthian Surge с тяжёлыми пресетами даёт шумы). Поэтому прогон 3 (16 голосов) и запас 30 % от критерия 70 % — обязательны. Следующий шаг после этого замера — та же нагрузка с настоящими движками (Surge XT, Dragonfly) через JACK.
