# Штука Дрюка: правила для всех сессий Claude

Это единственный свод правил. Его читают и облачная сессия (claude.ai Project «Штука Дрюка»),
и локальная (Claude Code на ПК). Новые правила не сочиняем: нужного нет, пишем предложение в `notes/handoff.md`.

## Источники правды (читать до работы, не переоткрывать заново)
1. `docs/ru/decisions/README.md`: индекс решений (короткий, читать всегда). Файл блока (`01_project` … `09_software`)
   открывать, только если задача его касается. Решения меняет только пользователь.
2. `docs/ru/README.md`: карта документов со статусами (рабочий, справка, частично, архив) и разделами, которые актуальны.
   Документ целиком не читать, только нужный раздел. `docs/ru/archive/` не читать без нужды.
3. `hardware/*/` (платы, `QUILTER.md`, `UNROUTED`), `.github/workflows/kicad.yml` (CI).
4. Навыки аккаунта: `shtuka-druka-design-rules`, `shtuka-druka-decisions`, `shtuka-druka-research`, `quilter-kicad-job`. Если локально не видны, спросить пользователя, но не писать свои версии.

## Версии: одна актуальная, без мусора (решение пользователя 13.11.2026)
- В репозитории у каждой вещи **одна текущая версия**. Новую ревизию пишем поверх того же файла с тем же именем;
  прежнюю хранит история git. Не заводим копий и папок вида `_v2`, `_old`, `_fixed`, `_pc`, `rev03/`, `cand_1_1/`.
- Веху отмечаем тегом git (`git tag m1-rev0.5`) или строкой в README платы, а не копией файлов.
- Эксперименты, кандидаты Quilter, сырые выгрузки, отчёты проверок, картинки сравнений живут **локально**
  (в `.gitignore`: `hardware/*/experiments/`, `hardware/*/quilter/results/`, `quilter/`). В репозиторий попадает только
  выбранный результат, на место рабочего файла платы; вывод из эксперимента — строкой в README платы или в `docs/ru/`.
- Рабочие копии для ручной работы (`hardware/*/almost/`) — только локально, в git не попадают. Выбранный результат
  переносим на место рабочего файла платы.
- Закрытые и устаревшие пункты журнала не копятся: устаревшее закрываем отметкой «устарело» с причиной.

## Как работаем вдвоём (облако + ПК)
- **Не тянем одеяло.** Работу делает тот, у кого есть инструмент:
  - облако: Quilter в браузере, поиск в интернете, исследования, документы, генераторы (`gen/*.py`), чтение CI;
  - ПК: KiCad MCP, DRC и GUI KiCad, Blender, Godot, всё, что требует локальных файлов и программ.
- **Экономия.** Перед задачей проверить журнал, `notes/handoff.md`, `git log`: может, уже сделано. Тяжёлое и рутинное
  (DRC, пересборки, проверки) отдаём стороне с нужным инструментом. Отчёты не пересылаем через пользователя, пишем в файл.
- **Один банк знаний.** Всё общее лежит в репозитории. Интернет-поиск можно, но выводы идут в `docs/ru/` или журнал.
- **Разногласия.** Не переписываем чужое. Обе позиции в `notes/handoff.md`, выбирает пользователь.
- **Синхронизация.** До работы `git pull --rebase`, после `git commit && git push`. Файлы сторон не пересекаем:
  каждый правит свой раздел в `notes/handoff.md`, чужие закрывает только отметкой.
